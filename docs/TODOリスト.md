# Lyndbaum 0からのバックポート候補と、今後追加したい機能などのリスト一覧

Lyndbaum 0（`~/develop/perl/lyndbaum0`）にある機能のうち、Lyndbaum 4に取り込めそうなものをまとめた。2026-10-20時点の調査。

## 前提

- 主な出どころは、lyndbaumの`docs/compat-diffs.md`（旧システムとの意図的な差分）と、各版のコミットメッセージ。

## これからやりたいこと

- 記事一覧で、ページを見分けて絞り込めるようにする

  - 絞り込み（すべて、記事、ページ）を足す。`load_arts_list`に`ctype`で選ぶオプションを足す
  - 非公開のページは表示順のツリーに出ないので、ここで絞り込んで辿れるようにする

  - この項目そのものを削除する
  - 「その他の設定」のタブに寄せる
- 設定ファイルの設定値の幾つかを管理画面に移す
  - 同時ログインセッションとかあんな所にあっても気づかない！！！

### テスト

- 回帰テスト
  - 画面と操作のテストは、`t/lib/AppTest.pm`で一時フォルダに空のデータで組み立て、`lyndbaum.cgi`を呼んで確かめる（本物の`data/`、`pub/`には触らない）
  - 作ったもの
    - 権限：`t/permission_screen.t`、`t/permission_action.t`。`skel/`に画面や操作を足したら、表に足さないとテストが落ちる
    - 画面：`t/screens.t`。開発モードで、管理画面とすべてのテーマの公開画面を開き、テンプレートのエラーや警告が出ないこと、参照する`pub/assets/`のファイルがあることを確かめる
    - 操作：`t/operations.t`。記事、コメント、NSFW、ブログの設定、プライベートモード、タグ、画像アルバム、エクスポートとインポート、再構築、ユーザー
  - 分かっている不具合は、テストでTODOにしている（下の「作業の途中で見つけたもの」）。直したらTODOを外す
  - まだ無いもの：デザイン編集の保存、プラグインの設定、記法タグのカスタマイズ、アップデート処理

## 取り込むのが難しい、または要らないもの

### 対応しない

- SQLiteへの対応（`docs/仕様/SQLiteに対応しない理由.md`）
  - DBの時間が画面全体のごく一部なので、SQLiteにしても速くならない（CGIではDBIの読み込みで遅くなる）
  - テキストDBは件数に比例して遅くなる（1万件で一覧32ms、10万件で約0.4秒）が、今のペースなら1万件に届くのは数十年先なので十分
  - MySQLとPostgreSQLも、同じ理由で使わず、テストも無いのでサポートから外した（v4.18）
- SQLiteを前提にした階層タグとファセット検索（閉包テーブル`tag_paths`）
  - adiary側を採用するため対応しない
- メディアブラウザ（ドラッグでの移動、フォルダの操作、範囲選択など）
  - adiary側を採用するため対応しない
- adiaryからのマイグレーション
  - 不要
- サイドバーのキャッシュなどの速度改善
  - adiaryは既に早いので対応不要
- 空行を挟んだリストをCommonMarkのリスト単位にする（`- a`、`- b`、空行、`- c`で全項目を`<p>`にする）
  - 項目単位のままにする（2026-10-21に決定）
- NSFW周りのメッセージ設定機能があるとよい可能性があるが面倒なのでやめた
  - このサイトは同性愛、成人向け要素を含み、高校生や18歳未満の方に適さない内容が含まれています。→内容を理解し、高校生でなく、18歳以上なので閲覧する
  - スコープを年齢に縛ることで「年齢確認を省略しています 確認を元に戻す」の文言はいじらずに済む
  - こんな冗長なもの想定する必要あるのかとか、そこにこだわりが必要かと言われると微妙…
  - 記事ごとにメッセージを設定したい需要とかが生まれると面倒なので忘れたほうがいいかもしれない…
- 記事のコメントで「※古いコメントもすべて表示」をしないと全部でないのをどうにかしたい
  - 素直にアンカーリンクを作れない
  - ページネーションか…？
    - ページネーションでアンカーリンクは地獄では…
      - どのページにいるかを持っていないとできない
  - 今のところ全表示でも困らないので単に全表示でもいいかも
  - 閲覧者にとっては余計な情報が減って便利かもしれないので一旦放置…？
- 前のページや次のページがない場合、ナビを非表示にする
  - 記事では消えるため対応する
  - なかったものが生えてくると何となく気持ち悪いのと、愚直にやると検索ページのレイアウトが崩れるので止めた
    - 両端のアンカータグがブロック要素で、flexで整えてる関係
    - 回避するにはdivでラップしないといけないので面倒
- セッション管理
  - ログイン中のセッションの一覧と、個別のログアウト
  - いるかこれ？

## 調べ方

出力は、`t/lib/MarkdownTest.pm`の`parse_md`に各入力を通して確かめた（`sectioning=0`）。
lyndbaumのテストケース（`t/markdown/*.txt`、同じ形式）をadiaryのパーサーに通して違いを見ると、不具合を探しやすい。
取り込むときは、先に`t/markdown/*.txt`へテストケースを書いてから直す。
直した後は`perl t/tools/corpus_diff.pl`で、全記事のうち出力が変わる記事を確かめる。保存済みのHTMLに反映するには、ブログを再構築する。
