# デバッグ方法

VSCodeでブレークポイントを置いてデバッグする方法。

## 準備

Ubuntu 26.04.1 LTS, Perl v5.40.1で確認。

```bash
sudo apt install build-essential libanyevent-perl libclass-refresh-perl libcompiler-lexer-perl \
libdata-dump-perl libio-aio-perl libjson-perl libmoose-perl libpadwalker-perl \
libscalar-list-utils-perl libcoro-perl

sudo cpan Perl::LanguageServer
```

VSCodeには拡張機能「Perl」（richterger.perl）を入れる。

## httpdで動かしてデバッグする

`.vscode/launch.json`の「lyndbaum.httpd.pl」で起動し、ブラウザで`http://localhost:8888/`を開く。`lib/`などに置いたブレークポイントで止まる。

この構成では、`lyndbaum.httpd.pl`に`-D`オプションを付けて起動する。`-D`を付けると次のように動く。

- リクエストを起動したプロセス自身で処理する（forkもスレッドも使わない）。Perl::LanguageServerのデバッガはfork後の子プロセスを扱えないため。
- ライブラリの自動リロードを止める（`SatsukiReloadStop`を設定する）。リロードでブレークポイントが外れないようにするため。
- `@INC`の`./lib`を、起動したスクリプトのパスを基準にした絶対パスにする。デバッガはブレークポイントを、VSCodeが開いているパスのままのファイル名で照合する。そのため、相対パスで読み込んだり、シンボリックリンクをたどった実体のパスで読み込んだりすると、ブレークポイントが効かない。

注意点。

- モジュールが読み込まれるまで、そのファイルのブレークポイントは無効（未確認）と表示される。最初のリクエストなどでモジュールが読み込まれると有効になる。

- 1プロセスなので、ブレークポイントで止まっている間はほかのリクエスト（CSSや画像も含む）が待たされる。
- 自動リロードしないので、コードを直したらデバッグを再起動する。
- ポート8888をほかのhttpdが使っているときは、`args`の`-p`を変える。
