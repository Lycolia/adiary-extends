# 機能一覧

adiaryの機能を、コードから洗い出した一覧。詳しい仕様は、必要になったものから`docs/仕様/`の下に書く。

- 調査の時点：2026-10-24（`ed230884`）
- 印
  - 【掃除候補】どこからも使われていない、外部のサービスが終わっているなど、消してよさそうなもの
  - 【要確認】動くかどうか、今も要るかどうかを確かめていないもの
  - 【不具合】動かないことが分かっているもの

## 権限の呼び方

| 呼び方         | コードでの判定 | 内容                                                           |
| -------------- | -------------- | -------------------------------------------------------------- |
| 誰でも         | なし           | ログインしていない人も含む                                     |
| ログイン中     | `Auth.ok`      | ログインしている人                                             |
| 編集者         | `v.allow_edit` | そのブログの管理者か、編集者に指定された人（ブログの権限設定） |
| ブログ管理者   | `v.blog_admin` | そのブログの管理者。システム管理者も含む                       |
| システム管理者 | `Auth.isadmin` | ユーザーの管理画面で管理者にした人                             |

## 1. 画面

画面は`skel/`の下のテンプレート。URLは`adiary.cgi?ディレクトリ/ファイル名`（`skel/set/detail.html`なら`?set/detail`）。

### 権限の確かめ方

- 管理画面の多くは、画面の中のメニュー（`_sub/menu_tree`。タブで出す）を出すときに、そのディレクトリの`_items.html`を呼び、そこで権限を確かめる（足りなければ403のページに切り替える）。メニューを出さない画面は、画面の中で自分で確かめる。
- `skel/set/`は`_dir_tree.html`で確かめる（ブログ管理者）。
- 2026-10-24の時点で、管理画面はすべて、どちらかの方法で権限を確かめている。

## 2. 操作（POSTとAjax）

### 振り分け

POSTの`action`の値で、呼ぶ処理を決める（`lib/SatsukiApp/adiary.pm`の`main`）。GETでは操作は動かない。

| `action`の形        | 呼ぶ処理                                             | 権限                                                            |
| ------------------- | ---------------------------------------------------- | --------------------------------------------------------------- |
| `_ajax_名前`        | 同じ名前のメソッド（`do_ajax_function`）。結果はJSON | `_ajax_login`以外はログイン中。そのうえでメソッドの中で確かめる |
| `ディレクトリ/名前` | `skel/ディレクトリ/_action/名前.html`                | 操作の中で確かめる（下の表）                                    |

- 操作の中の権限の確かめ方は2通りある。操作の冒頭（`ifbreak(!v.allow_edit)`など）で確かめるものと、呼び出し先の関数の中（`Operation not permitted`を返す）で確かめるもの。
- 2026-10-24の時点で、ログインを前提にした操作はすべて、どちらかの方法で権限を確かめている。

### CSRFの対策

- 確認キー（CSRFトークン）は使っていない。原作者がVer3.50で、Cookieの`SameSite`で足りるとして除去した（https://adiary.adiary.jp/0422）。4.09で、その消し残し（いくつかのフォームの`csrf_check_key`の欄と、それを送るJavaScript）を消した。
- ログインのCookieに`SameSite=Lax`を付けている（`lib/Satsuki/Base_2.pm`の`put_cookie`。`CookieSameSite`で変えられる）。ほかのサイトからのPOSTにはCookieが送られないので、ログイン中の操作をさせられることはない。
- 同じサイトの中からのPOSTは`SameSite`では防げない。そのため、記事の本文にはフォームの部品（`form`、`input`、`button`、`select`、`textarea`など）を書けないようにしている（4.09、`info/allow_tags_article.txt`）。書けると、ほかのユーザーが記事に管理画面の操作へ送るフォームを置き、システム管理者に押させることができる。

## 3. 設定

設定は3か所に分かれている。

| 置き場所                                                         | 変える画面                          | 内容                                                   |
| ---------------------------------------------------------------- | ----------------------------------- | ------------------------------------------------------ |
| `adiary.conf.cgi`（gitの管理外。見本は`adiary.conf.cgi.sample`） | なし（ファイルを書き換える）        | DB、ログイン、アップロードの拡張子など、サーバーの設定 |
| `data/system_config.dat`（既定値は`info/default_config.dat`）    | `?system/setting`（システム管理者） | メンテナンスモード、キャッシュなど、システム全体の設定 |
| `data/blog/setting.dat`（既定値は`info/default_setting.dat`）    | `?set/`など（ブログ管理者）         | ブログごとの設定                                       |

- 新しいブログの設定の既定値は、`info/default_setting.dat`。
- ブログの設定に項目を足したときは、値が空なら既定値を使うようにする（今あるブログの`setting.dat`には、その項目が無いため）。

### 3.1 設定ファイル（`adiary.conf.cgi`）

| 項目                                                   | 内容                                                       | 備考                                                                                                                                          |
| ------------------------------------------------------ | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `$DB`                                                  | DB（テキストDB、PostgreSQL、MySQL）                        | 既定はテキストDB（`data/db/`）                                                                                                                |
| `v.trust_mode`、`v.admin_trust_mode`                   | HTMLのタグの制限をなくす（全員／管理者だけ）               | 見本では`admin_trust_mode`がON                                                                                                                |
| `v.uplaod_files_max`                                   | 1回のアップロードの合計の上限                              | つづりは`upload`ではないが、使う側も同じつづり                                                                                                |
| `v.system_email`、`v.system_smtp`など                  | メールの送信元とSMTP                                       | 新着コメントの通知（`notify_mail`）などで使う                                                                                                 |
| `Auth.expires`、`Auth.max_sessions`、`Auth.all_logout` | ログインの保持時間、多重ログインの数と扱い                 |                                                                                                                                               |
| `Auth.fail_count`、`Auth.fail_minute`                  | ログインに続けて失敗したときに、しばらくログインさせない   |                                                                                                                                               |
| `Auth.allow_ip`、`Auth.allow_host`                     | ログインできるIPアドレスとホスト名                         |                                                                                                                                               |
| `Auth.pass_min`                                        | パスワードの最低文字数                                     | 既定は4。4.09より前の見本では`auth`が小文字になっていた                                                                                       |
| `Auth.start_up`                                        | システム管理者がいないときの自動ログイン                   | 初期セットアップ用                                                                                                                            |
| `If_post_exec_pre`                                     | POSTの前の処理（フォームの大きさの上限、ホスト名の逆引き） | `resolve_host()`もTODO「ホスト名まわり」の対象                                                                                                |
| `v.parsers`                                            | 使えるパーサーの一覧                                       |                                                                                                                                               |

### 3.4 サブドメインモード（削除）

`v.subdomain_mode`で、ブログを`ブログID.ドメイン`で表示する機能があったが、4.09で削除した。HTTPSのときにほかのブログへのリンクが`http://`になる、`default_blogid`が入っていると働かない、ログインのCookieを全ブログで共有するなどの問題があり、保守の手間に見合わないため。設定ファイルに`v.subdomain_mode`が残っていても無視する。

### 3.5 複数のブログ（削除）

1つのadiaryで複数のブログを持つ機能は、4.10で削除した。ブログは1つだけにする。ユーザーを複数持つ機能と、ブログの権限設定（管理者・編集者・閲覧者）は残す。

- 削除した：ブログの一覧（`?blogs`、`?blogs_sys`、システム設定の`blogs_allow`）、任意のブログの作成（`?system/blog_create`、ほかのブログのコピー）、ブログの削除（`?mainte/blog_drop`。全記事の削除は`?mainte/blog_clear`として残した）、アルバムのブログ一覧（ブログの設定の`album_blogs`）、システム設定の`create_blog_only_admin`とデフォルトブログの選択、新しいブログの初期設定の編集（`?set/…&blogid=*`と、保存先の`data/default_setting.dat`。ファイルが残っていても読まない）
- ブログの作成：ブログがまだ無いときだけ、システム管理者が`?etc/myblog_create`から作れる
- ブログIDは持たない。テーブル名、データのフォルダ、公開フォルダは決まった名前（「5. データ」）。ユーザーIDとブログIDが同じ人をブログ管理者とみなす判定も無くし、ブログ管理者はシステム管理者と、権限設定で指定した人だけ
- URL：いつもそのブログを表示する。`/ブログID/`のURLでほかのブログを表示する振り分けは無くした（`/ブログID/…`は記事のURLとして扱う）。ブログを見られないときは、ブログがまだ無いか、見る権限が無い旨を出す
- 非公開モード：公開フォルダの名前に乱数を付け足して画像のURLを隠す仕組み（`blogpub_dir_postfix`、システム設定の`dir_postfix_len`）は削除した。非公開モードは記事を隠すだけで、添付ファイルはURLが分かれば見られる
- 4.10のアップデート処理（`migrate_410`）で、データを新しい持ち方に移す。各バージョンの処理より先に行う
  - 移すブログは、`default_blogid`のブログ、無ければ`_bloglist`のブログIDの順で最初のブログ。ほかのブログのテーブルとフォルダは残すが、使わない
  - テーブルの名前を変える（`ブログID_art` → `art`など。DBの`rename_table`）。`data/blog/ブログID/`の中身を`data/blog/`へ、`pub/ブログID/image/`を`pub/attachments/`へ（`adiary/`は`posts/`に改名）、`pub/ブログID/`の残りを`pub/`へ移す
  - 記事・更新履歴・ゴミ箱の原文の記法（`[image:…:adiary/…]`、`[file:…:adiary/…]`）を`posts/`に、アイキャッチ（`main_image`）とブログの設定の中のパスを新しいパスに、アップロード先（`edit_upload`）の`adiary/`を`posts/`に書き換える
  - ブログに写したプラグインの処理が古いテーブル名を使っているので、すぐにプラグインを再インストールする。その後、全記事の再構築、プラグインの再インストール、カスタムCSSの作り直しを行う
  - `_bloglist`のテーブルと、システムの情報の`default_blogid`、`dir_postfix_len`を消す
  - 記事の原文に手で書いた旧パス（`pub/ブログID/…`）は書き換えない。Webサーバーで転送する（`docs/nginx.md`）
- 全ブログに対する処理：システム管理の再構築・付加情報の再生成・プラグインの再インストール・カスタムCSSの作り直しと、アップデート処理は、そのブログだけを処理する
- ほかのブログへのリンクの記法（`[id:ブログID]`、`[id:ブログID:記事]`）と、エクスポートの「id記法を通常リンクに書き換え」（`id2link`）も削除した

### 転送（`redirect()`）

- テンプレートの中からでも、Perlの側（`main`の中）からでも呼べる。転送のページを出した後、`die("Break")`で処理を抜ける。
- Perlの側から呼んだときは、`Satsuki::Base`の`start_up`で`Break`を受け止め、終わりの処理（`finish()`）まで進める。
- テンプレートの中から呼んだときは、`$ROBJ->{Redirected}`の印を立て、`output_html`でページを出さない。
- 4.09より前は、Perlの側から呼ぶと302の後ろに500のエラーが付いて`finish()`が飛び、テンプレートの中から呼ぶと302の後ろにページ全体をもう一度出していた。

### Amazonの記法（削除）

- `[asin:…]`、`[isbn:…]`、`[amazon:…]`の記法（`Tag_amazon.pm`）、さつき記法でAmazonの商品のURLを商品のリンクに変える処理（`Tag_url_filter.pm`）、ブログの設定のアフィリエイトID（`asid`）を、4.09で削除した。
- 商品名は手で書く必要があり、画像は`ws-fe.amazon-adsystem.com`が使えなくなって、代わりのURLでも一部の商品でしか出ず、ふつうのリンクとほとんど変わらなかったため。PA-APIは使っていなかった。
- AmazonのURLは、ほかのURLと同じふつうのリンクになる。

### はてなの検索の記法（削除）

- `[search:keyword:…]`、`[search:question:…]`、`[search:asin:…]`、`[search:web:…]`と、別名の`[search:k:…]`、`[search:q:…]`は、はてなの検索（`search.hatena.ne.jp`）へのリンクを作る記法だったが、はてなの検索サービスが終わり、どれもはてなのトップページへ転送されるだけだったので、4.09で削除した。`search:asin`（はてなASIN検索）は、Amazonの記法とは関係ない。

| `pub/attachments/`               | 添付ファイル（画像など）。アルバムの根元。記事の画像は`posts/年/`（アップロード先の既定値`posts/%y/`）、ブログの画像やアイコンは`@system/`、ゴミ箱は`.trashbox/`  |
| `pub/assets/`                    | 配布物の公開するファイル。gitで管理するのはここだけ（Lyndbaumと同じ）。`js/`（JavaScript）、`theme/`（テーマ）、`dist/`（ロゴ、アルバムのアイコン、フォントなど） |

公開フォルダと非公開のフォルダ

- 公開するのは`pub/`だけ。4.10までルートにあった`js/`、`pub-dist/`、`theme/`は、4.11で`pub/assets/js/`、`pub/assets/dist/`、`pub/assets/theme/`に移した。`adiary.conf.cgi`の定数`script_dir`、`pubdist_dir`、`theme_dir`がこの場所を指す
- ブログが作るファイル（テーマのカスタムCSSの`pub/css/`、動的CSSの`pub/css.d/`と`dynamic.css`、プラグインのJavaScriptの`pub/js/`）は`pub/`の直下のまま
- `__cache/`、`data/`、`info/`、`lib/`、`plugin/`、`skel/`、`skel.local/`、`docs/`、`t/`は非公開。`.htaccess`（Apacheと`adiary.httpd.pl`）で拒否する。nginxでは`location`で拒否する（`docs/nginx.md`）
- コンテンツのキー（記事のURLの名前）の先頭の階層には、ルートにあるファイルやフォルダの名前は使えない（`check_link_key_path`。ルートを実際に一覧して調べる）。4.11で`js`、`pub-dist`、`theme`が使えるようになった
- 4.11のアップデート処理では、`pub-dist/`のパスを出す記法（`[mj:…]`、`[icon:…]`、`[pubdist]`）を使った記事だけを作り直し、プラグインの再インストールとカスタムCSSの作り直しを行う。記事の原文に手で書いた古いパスは書き換えず、Webサーバーで転送する（`docs/nginx.md`）
