# 機能一覧

adiaryの機能を、コードから洗い出した一覧。詳しい仕様は、必要になったものから`docs/仕様/`の下に書く。

- 調査の時点：2026-10-24（`ed230884`）
- 印
  - 【掃除候補】どこからも使われていない、外部のサービスが終わっているなど、消してよさそうなもの
  - 【要確認】動くかどうか、今も要るかどうかを確かめていないもの
  - 【不具合】動かないことが分かっているもの

## 権限の呼び方

| 呼び方             | コードでの判定  | 内容                                                                 |
| ------------------ | --------------- | -------------------------------------------------------------------- |
| 誰でも             | なし            | ログインしていない人も含む                                           |
| ログイン中         | `Auth.ok`       | ログインしている人                                                   |
| 編集者             | `v.allow_edit`  | そのブログの管理者か、編集者に指定された人（ブログの権限設定）       |
| ブログ管理者       | `v.blog_admin`  | そのブログの管理者。システム管理者も含む                             |
| システム管理者     | `Auth.isadmin`  | ユーザーの管理画面で管理者にした人                                   |

## 1. 画面

画面は`skel/`の下のテンプレート。URLは`adiary.cgi?ディレクトリ/ファイル名`（`skel/set/detail.html`なら`?set/detail`）。

### 権限の確かめ方

- 管理画面の多くは、左のメニュー（`_sub/menu_tree`）を出すときに、そのディレクトリの`_items.html`を呼び、そこで権限を確かめる（足りなければ403のページに切り替える）。メニューを出さない画面は、画面の中で自分で確かめる。
- `skel/set/`は`_dir_tree.html`で確かめる。`?set/…&blogid=*`（新しいブログの初期設定の編集）はシステム管理者、それ以外はブログ管理者。
- 2026-10-24の時点で、管理画面はすべて、どちらかの方法で権限を確かめている。

## 2. 操作（POSTとAjax）

### 振り分け

POSTの`action`の値で、呼ぶ処理を決める（`lib/SatsukiApp/adiary.pm`の`main`）。GETでは操作は動かない。

| `action`の形          | 呼ぶ処理                                         | 権限                                               |
| --------------------- | ------------------------------------------------ | -------------------------------------------------- |
| `_ajax_名前`          | 同じ名前のメソッド（`do_ajax_function`）。結果はJSON | `_ajax_login`以外はログイン中。そのうえでメソッドの中で確かめる |
| `ディレクトリ/名前`   | `skel/ディレクトリ/_action/名前.html`            | 操作の中で確かめる（下の表）                       |

- 操作の中の権限の確かめ方は2通りある。操作の冒頭（`ifbreak(!v.allow_edit)`など）で確かめるものと、呼び出し先の関数の中（`Operation not permitted`を返す）で確かめるもの。
- 2026-10-24の時点で、ログインを前提にした操作はすべて、どちらかの方法で権限を確かめている。

### CSRFの対策

- ログインのCookieに`SameSite=Lax`を付けている（`lib/Satsuki/Base_2.pm`の`set_cookie`。`CookieSameSite`で変えられる）。外のサイトからのPOSTにはCookieが送られないので、ログイン中の操作をさせられることはない。
- サブドメインモードでは、ブログどうしが同じサイト（same-site）になるため、`SameSite=Lax`では防げない。【要確認】
- `csrf_check_key`の欄が画像アルバム、インポート、エクスポートなどのフォームにあり、`js/edit.js`なども送っているが、値の元の`CSRF_check_key`がどこにも定義されておらず、値はいつも空で、サーバーも確かめていない。【掃除候補】
  - `js/adiary.js`の「セキュリティコードの設定」にある、`csrf_check_key`の欄があればトークンを入れない処理も、コメントフォームにこの欄が無いので働いていない。
- 【要確認】記事の本文には`<form>`と`<button>`を書ける（`info/allow_tags_article.txt`）。複数のユーザーがブログを持っている環境では、あるユーザーが記事に管理画面の操作（たとえば`_ajax_user_add`）へ送るフォームを置き、システム管理者にそのボタンを押させると、管理者の権限で操作が行われる。同じサイトの中からのPOSTなので`SameSite=Lax`では防げず、確認キー（`csrf_check_key`）も働いていない。ユーザーが自分1人だけなら影響はない。

## 3. 設定

設定は3か所に分かれている。

| 置き場所                                  | 変える画面               | 内容                                         |
| ----------------------------------------- | ------------------------ | -------------------------------------------- |
| `adiary.conf.cgi`（gitの管理外。見本は`adiary.conf.cgi.sample`） | なし（ファイルを書き換える） | DB、ログイン、サブドメインモード、アップロードの拡張子など、サーバーの設定 |

### 3.4 サブドメインモード

`v.subdomain_mode`にドメイン（例：`blog.example.com`）を書くと、ブログを`ブログID.blog.example.com`で表示する。2026-10-24に、スクラッチパッドに写した環境で、mod_rewriteで動かしたときの環境変数を与えて試した。

| 状況 | 結果 |
| ---- | ---- |
| `https://lycolia.blog.test/`、記事のURL | 表示できる。ページの中のリンクは`/0805`のような相対の形、OGPなどの絶対URLも`https://` |
| `https://blog.test/lycolia/0811` | `//lycolia.blog.test/0811`へ転送する。ただし後ろに500のエラーが付く（下の「Perlの側からの転送」） |
| `?login` | ブログのドメインでも親のドメインでも表示できる |
| `?blogs`のリンク | 【不具合】HTTPSのサイトでも`http://lycolia.blog.test/`になる |

#### 分かっている問題

- 【不具合】ほかのブログへのリンクが`http://`になる。`get_blog_path`が`v.subdomain_proto`（既定は`http://`）を使うため。`subdomain_proto`は設定ファイルの見本に書かれていない。`get_blog_path`は、記事の中の`[adiary:…]`記法、ブログの一覧、ブログの作成、ユーザーの一覧などで使っている。
- 【不具合】スマホ用のテーマ（`theme/_sphone/_skel/_header.html`）の「ようこそ」のリンクが`http://`で固定。
- 【要確認】`default_blogid`（デフォルトのブログ）が入っていると、サブドメインモードより優先され、サブドメインモードが働かない。システム設定の保存では空にするが、それより前に入っていた値は残る。
- 【要確認】ログインのCookieを、既定ではすべてのブログのドメインで共有する（`v.subdomain_secure`がOFFのとき）。`HttpOnly`は付くのでJavaScriptからは読めない。
- 【要確認】ブログどうしが同じサイト（same-site）になるので、`SameSite=Lax`でCSRFを防げない（2. 操作の「CSRFの対策」）。
- 【要確認】サブドメインモードでは、`HTTP_HOST`の書き換え対策（`secure_http_host`）を飛ばしている。

### Perlの側からの転送

- 【不具合】`$ROBJ->redirect()`をテンプレートではなくPerlの側（`main`の中）から呼ぶと、302を出した後に`die("Break")`が受け止められず、`adiary.cgi`の`eval`まで抜ける。そのため、終わりの処理（`$ROBJ->finish()`）が動かず、302の本文の後ろに500のエラーの文面（`Break at lib/Satsuki/Base.pm line 525.`）が付く。ブラウザは先に302を受け取るので、転送はされる。
  - 起きる場所：存在しない画面を開いたとき（`select_skeleton`）、アルバムモードのブログのトップ（`select_default_skeleton`）、サブドメインモードで親のドメインからブログのパスを開いたとき（`blogid_and_pinfo`）。
