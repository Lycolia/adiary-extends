# lyndbaumからのバックポート候補

lyndbaum（`~/develop/perl/lyndbaum`）にある機能のうち、adiary-extendsに取り込めそうなものをまとめた。2026-10-20時点の調査。

## 前提

- 主な出どころは、lyndbaumの`docs/compat-diffs.md`（旧システムとの意図的な差分）と、各版のコミットメッセージ。
- 取り込み済みのもの（`patch/markdown-parser`）：
  - コードスパンの中の`\`（`2550dc5f`）
  - 脚注記法（`7b3a21b6`）
  - リンクの文字の中の角括弧、リンク先の入れ子の括弧、HTMLに無いタグ名を文字で出す、リストの項目の先頭の`>`、見出しの無い`[*toc]`、表のセルの中の`\|`（`debacce2`）
  - 表のセルの分け方をGFMに合わせる（`\\|`の`|`は区切り）、表の1列目の左寄せ（`6b1bc696`）
  - 空白に挟まれた`*`・閉じていない`**`を強調にしない、日本語に挟まれた`_`を強調にしない、`*強調*`、バナーやキャプション付きの画像を`<p>`で囲まない（`87dc4d67`）
  - 代替テキストを省いた画像の`title`をタグ名にしない、代替テキストの`:`、名前を省いた添付ファイルのリンクの文字（`a81f70a2`）
  - 段を飛ばした見出しを目次で1つ上の段に繰り上げる（`2db777fd`）
  - 編集画面の画像・添付ファイルの挿入で、ファイル名を代替テキストや名前に入れない（`f383803e`、`e48f1112`）
  - 記事の原文から、ファイル名と同じ代替テキストや名前を落とすスクリプト（`t/tools/drop_filename_alt.pl`、`6916bcba`、`86d47f0d`）。2026-10-20に実行済み（画像320記事・5913か所、添付ファイル5記事・10か所）
  - 脚注が1段落のときも改行を`<br />`にする、効いていない`lf_patch`を消す（`58ba2760`）
  - 入れ子のリストやコードフェンスの中の空行で、外側の項目を`<p>`で囲まない。`<p>`を付けるかは項目ごとに決める（`997506f4`）
- レスポンシブデザイン・Markdownパーサー・バックリンク・Fancyboxのスクリプトダイエットが目的
  - 直せるなら管理画面のメインUIも直していいかもしれないが規模がデカそう？
  - ギャラリーは一旦そのままにしておく

なし（2026-10-21時点）。

## D. 取り込むのが難しい、または要らないもの

### 対応しない

- SQLiteを前提にした階層タグとファセット検索（閉包テーブル`tag_paths`）
  - adiary側を採用するため対応しない
- メディアブラウザ（ドラッグでの移動、フォルダの操作、範囲選択など）
  - adiary側を採用するため対応しない
- adiaryからのマイグレーション
  - 不要
- サイドバーのキャッシュなどの速度改善
  - adiaryは既に早いので対応不要
- 空行を挟んだリストをCommonMarkのリスト単位にする（`- a`、`- b`、空行、`- c`で全項目を`<p>`にする）
  - 項目単位のままにする（2026-10-21に決定）

### adiaryにすでにあるもの

- FastCGI（`adiary.fcgi`）
- サイトマップ（`plugin/sitemap`）
- 前後の記事へのリンク
- `<head>`に入れるHTML（`dem_javascript`などのプラグインが近い）
- 新着コメントの通知

## 調べ方

出力は、`t/lib/MarkdownTest.pm`の`parse_md`に各入力を通して確かめた（`sectioning=0`）。
lyndbaumのテストケース（`t/markdown/*.txt`、同じ形式）をadiaryのパーサーに通して違いを見ると、不具合を探しやすい。
取り込むときは、先に`t/markdown/*.txt`へテストケースを書いてから直す。
直した後は`perl t/tools/corpus_diff.pl`で、全記事のうち出力が変わる記事を確かめる。保存済みのHTMLに反映するには、ブログを再構築する。
