# lyndbaumからのバックポート候補

lyndbaum（`~/develop/perl/lyndbaum`）にある機能のうち、adiary-extendsに取り込めそうなものをまとめた。2026-10-20時点の調査。

## 前提

- 主な出どころは、lyndbaumの`docs/compat-diffs.md`（旧システムとの意図的な差分）と、各版のコミットメッセージ。
- レスポンシブデザイン・バックリンク・Fancyboxのスクリプトダイエットが目的
  - 直せるなら管理画面のメインUIも直していいかもしれないが規模がデカそう？
  - ギャラリーは一旦そのままにしておく

## A. Markdownの残りの不具合

なし（2026-10-21時点）。

## C. パーサー以外で取り込めそうなもの

| 項目                                | 内容                                                            | 規模・備考                                                           |
| ----------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------- |
| 参照元（バックリンク）              | その記事へリンクしている記事の一覧を記事の下に出す              | 中。adiaryには見当たらない                                           |
| 目次の追従表示                      | スクロールしても見出しの目次がついてくる                        | 小〜中。JSとテーマが中心                                             |
| 段を飛ばした見出しの警告            | `#`の無い`##`などを、編集の画面で指摘する                       | 小〜中。目次には繰り上げて出すようにした（`2db777fd`）ので、急がない |
| コードの色付けの言語の別名          | `ps1`→`powershell`、`c#`→`csharp`（大文字と小文字は区別しない） | 小。数行で済む                                                       |
| 画像の拡大表示をLythumbに置き換える | FancyboxからLythumb-viewer（AGPLv3、自作）へ                    | 中。属性が`data-fancybox`から`data-lythumb`に変わる                  |
| コメントの`>>N`のリンク             | `#cN`へのリンクにする                                           | 小。adiaryにすでに同じものがあるかは未確認                           |

| パスワードのbcrypt化                | セキュリティ強化、やってもやらなくてもどうでもよさそうではある  | 小。恐らく私しかユーザーがいないので影響はない                       |

## D. 取り込むのが難しい、または要らないもの

### 対応しない

- SQLiteを前提にした階層タグとファセット検索（閉包テーブル`tag_paths`）
  - adiary側を採用するため対応しない
- メディアブラウザ（ドラッグでの移動、フォルダの操作、範囲選択など）
  - adiary側を採用するため対応しない
- adiaryからのマイグレーション
  - 不要
- サイドバーのキャッシュなどの速度改善
  - adiaryは既に早いので対応不要
- 空行を挟んだリストをCommonMarkのリスト単位にする（`- a`、`- b`、空行、`- c`で全項目を`<p>`にする）
  - 項目単位のままにする（2026-10-21に決定）

### adiaryにすでにあるもの

- FastCGI（`adiary.fcgi`）
- サイトマップ（`plugin/sitemap`）
- 前後の記事へのリンク
- `<head>`に入れるHTML（`dem_javascript`などのプラグインが近い）
- 新着コメントの通知

## E. 作業の途中で見つけたもの

lyndbaumとは関係なく、adiaryで見つけた問題。

| 項目                                           | 内容                                                                                                                      | 備考                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 記事の削除で記事ファイルが残る                 | インデックス（`#index.dat`）の行だけが消え、記事ファイルが残っていた（401、402、568、600、772。2026-10-20に手で削除済み） | コンテンツページだけでなく普通の記事（600、772）でも起きている。同じ時刻のファイルが組になっている（568と772、401と402）ので、1回の操作で起きたらしい。ゴミ箱（`lycolia_trash`）にも無かった。削除・移動の処理で、インデックスとファイルを消す順番と、途中で失敗したときの扱いから調べる |
| ファイル名に説明が入っていた画像の代替テキスト | `drop_filename_alt.pl`で、ファイル名に入っていた説明も一緒に消えた（482の「10年前のらしい」、504の「除湿機」）            | 必要なら代替テキストを手で書き足す。元の原文は`data/tmp/drop_filename_alt-20261020113644/`にある                                                                                                                                                                                         |
| HTMLの記事の画像の挿入                         | 編集画面で、`alt="%f"`（ファイル名）を入れている                                                                          | さつき記法とMarkdownは直した（`f383803e`）。HTMLの記事は未対応                                                                                                                                                                                                                           |

## 調べ方

出力は、`t/lib/MarkdownTest.pm`の`parse_md`に各入力を通して確かめた（`sectioning=0`）。
lyndbaumのテストケース（`t/markdown/*.txt`、同じ形式）をadiaryのパーサーに通して違いを見ると、不具合を探しやすい。
取り込むときは、先に`t/markdown/*.txt`へテストケースを書いてから直す。
直した後は`perl t/tools/corpus_diff.pl`で、全記事のうち出力が変わる記事を確かめる。保存済みのHTMLに反映するには、ブログを再構築する。
